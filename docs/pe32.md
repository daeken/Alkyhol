# Experimental PE32 execution in a 64-bit Rosetta host

Alkyhol now executes an unchanged owned i386 Windows PE32 binary on the physical
M4 through a 64-bit Mach-O host. This is checked loading plus CPU mode gates, not
static instruction rewriting, a 32-bit Mach-O, or a general Win32/game runtime.
The user-selected next application target is their local DAOrigins executable;
it has not executed. Native-backed partial-image-page handling clears its previous
SizeOfImage gate. Native-backed handling of non-mapped certificate metadata now
clears its next file-range gate. Checked static TLS data now clears that startup
gate as well. Legacy cookie configuration is now supported; local preflight
stops at the explicit SafeSEH exception-dispatch gate before entry. Game binaries, packaged game wrappers and all
header/import inventories remain ignored/local and are never sent to CI.

```sh
python3 tools/build_pe32_fixture.py
python3 tools/run_pe32_probe.py --fixture local/pe/pe32/pe32.exe --output local/pe/pe32/observation.json
python3 tools/translate_pe32.py /path/to/trusted.exe --output local/pe/program32-macos
local/pe/program32-macos --inspect
local/pe/program32-macos
```

## CPU and address-space contract

The host links with a 4-KiB __PAGEZERO so low guest address space is available.
MAP_32BIT allocations are checked below 4 GiB without MAP_FIXED or replacing host
mappings. Image bases are 64-KiB aligned; the stack has inaccessible guard pages.
Two unused LDT slots (512/513) supply flat 32-bit code/data descriptors and remain
reserved for this process lifetime. A third slot (514) supplies a per-image FS/TEB
descriptor only during an exclusively leased CPU entry. Occupied slots fail before
being overwritten; concurrent entries fail instead of retargeting another TEB.
On this Rosetta version, automatic LDT allocation and multi-selector installation
abort the process; the implementation explicitly queries these slots and installs
one descriptor per call. Initial isolated experiments observed those limitations.

Original MIT assembly switches into 32-bit code using a far return. Low far-jump
gates switch to 64-bit code at imports, return to the saved host stack, call Rust,
then resume a per-import 32-bit RET-immediate stub with the correct stdcall cleanup.
A final gate returns the DWORD entry result to the host. Host nonvolatile registers
and DS/ES/SS/FS selectors are saved/restored; EBX/ESI/EDI/EBP survive API calls.
Host FS must be unused (selector zero). Host FS is restored before Rust calls,
and guest FS is reinstalled before returning to i386 code. GS is untouched.
Actual DS/ES/SS/FS/GS selectors are compared before/after entry; the leased FS
descriptor is cleared before successful return. No Wine code is copied.

## Loader and API subset

`Image::parse_i386` explicitly selects PE32/i386 headers, 32-bit ImageBase,
directory offsets and four-byte import slots. Existing AMD64 constructors still
reject PE32. Bitness, section bounds/W^X, initialized entry, directory backing,
names/ordinals, arithmetic/32-bit address limits and overlapping fixups are checked.
HIGHLOW relocation may adjust initialized instruction operands or section data
before RX/RO protections; header/BSS writes and unsupported kinds fail. IAT/HIGHLOW
write overlap is rejected. Bounded single-thread static TLS data is enabled for
SizeOfZeroFill=0 with no callbacks. Current startup gates reject TLS callbacks,
nonzero SizeOfZeroFill, SafeSEH dispatch, other active load-config/CFG fields,
bound/delay imports, exception directories, CLR and other existing
unsupported features. For PE32 with 4-KiB section alignment, a partial final image
page now rounds the allocation extent up while retaining the original header
value in `Image::declared_size()`. Section extents must still fit the rounded
mapping, and the one-GiB/32-bit address bounds remain. AMD64 and other section
alignments retain their existing alignment gates. No input header is rewritten.

PE32 certificate directory fields are retained as untrusted file-offset/size
metadata through `certificate_directory()`, without reading or mapping through
them. Ordinary loading does not verify signatures. Explicit FORCE_INTEGRITY
requests fail as unsupported; partial directory pairs remain rejected. The AMD64
certificate file-backing gate and all mapped-directory/section bounds remain.
Callers must separately bound any attempted certificate inspection.

`LoadedImage32::load(bytes, rebase, &process)` preflights every feature/import,
creates the checked image, low gates and guarded stack, and borrows ProcessContext
through cleanup. Unsafe `enter` executes trusted code; it rejects nested entry.
The kernel32 bridge supports GetLastError, SetLastError, GetStdHandle, synchronous
WriteFile, GetModuleHandleA/W(NULL) and GetProcAddress for the current executable.
Named module lookup, other module handles and absent export tables remain explicit
unsupported forms. Export-query names must be bounded ASCII in readable guest
section/stack storage; empty/non-ASCII/unreadable names fail before dereferencing
outside checked storage. Success preserves last-error state; tested missing names
return NULL/error 127, and tested out-of-range ordinals return NULL/error 182. Standard handles use actual host stream handles behind explicit four-byte
proxies. Arguments are copied before host calls, allowing output pointers to
alias guest argument words without retaining a Rust reference to that storage.
WriteFile buffers/count output must lie in permitted image/stack ranges,
with DWORD-aligned stack/count pointers;
overlap must be NULL, and writes are bounded to one MiB. Unknown imports fail
before entry; unsupported runtime forms terminate with diagnostic/status 78.

A minimal one-page TEB supplies FS-relative self, stack bounds and last error.
Imported APIs and direct FS last-error writes share the same field. Other TEB
fields are outside this runtime contract. Static TLS explicitly installs its
vector; a zero PEB field and empty SEH-chain marker do not implement those facilities.
There is no PEB, CRT startup, DLL execution/loading, TLS callbacks,
SEH, guest threads, Windows syscall or binary graphics/COM support on this path.
Only integer/stdcall results are implemented; full floating-point/exception state
and additional calling conventions remain separate. Input instructions are trusted
native code, not statically validated or sandboxed. Existing PE64 runtime/source
compatibility and direct Metal APIs remain separate, preserved paths.

## Finite evidence

An original MIT no-CRT PE32 observer executes 10,000 imported last-error round trips,
checks four-byte pointer width and original relocated data-pointer identity, and
writes eight exact DWORDs using a real five-argument stdcall WriteFile. An assembly
canary checks EBX/ESI/EDI/EBP/ESP preservation and a one-byte 32-bit INC wrapping
EAX; that opcode has different semantics in 64-bit mode. Physical M4/Rosetta normal
and forced-rebase runs pass. The identical PE is transferred to native Windows
for independent execution through the existing workflow. Downloaded clean native
Windows/hosted Mac records and clean physical M4 execution at `63b6f53` agree on
all eight raw words and exact executed PE/source identities. The complete native
record at `pe/reference/pe32-windows-v1.json` is frozen and required by default.
Hashes cover exact source/executed PE bytes and clean revision.
See [validation](validation.md) for actual revisions/results.

Hardened strict-reference revision `796e395` passes all three PE and 24 conformance
CI jobs. Downloaded Windows/hosted Mac reports and fresh clean physical M4
execution agree at that same revision on all eight raw words and exact executed
PE/source identities, including host normal/forced-rebase execution. Older frozen
PE64, released applications, DLL, SDK/source/COM, shader and Metal checks pass.

Synthetic portable tests separately cover header formats, truncation, width/address
bounds, named/ordinal/fallback imports, malformed tables and HIGHLOW boundaries,
including real instruction-operand targets. Host units check buffer permissions,
stack edges and overflow without executing fake mappings. Compiler checks enforce
the process-guard lifetime. These finite observations do not establish CRT, game
startup or rendering compatibility.

Primary background: Wine's [macOS WineConf 2022 presentation](https://indico.freedesktop.org/event/2/contributions/92/attachments/87/140/Wine%20on%20macOS%20State%20of%20the%20Union%20-%20WineConf%202022.pdf)
documents 32-bit code segments under Rosetta. [Wine 9.0 release notes](https://list.winehq.org/hyperkitty/list/wine-announce%40list.winehq.org/message/TB7WYKWZF4DWNQLWN3XZM2NLEAF6MKST/)
describe the 32-bit PE/64-bit Unix boundary. [Pinned Wine 11.0 source](https://github.com/wine-mirror/wine/blob/wine-11.0/dlls/ntdll/unix/signal_x86_64.c)
shows macOS LDT usage; Apple's installed `i386/user_ldt.h` declares the LDT APIs.
Microsoft's [PE/COFF format](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format)
and [stdcall contract](https://learn.microsoft.com/en-us/cpp/cpp/stdcall) define the
binary layout and calling convention. External implementation descriptions are
background; the physical tests above are Alkyhol's actual execution evidence.

## Image-size geometry observer

The next native evidence probe changes only SizeOfImage in separate copies of the
unchanged frozen **owned** PE32 test. It never accepts game inputs and leaves the
original fixture untouched. Eight cases cover its aligned size, the previous
byte, last virtual/initialized section ends, one byte into the final page, the
final page start/previous byte and zero. The Windows collector records exact
CreateProcess winerror/errno when no child starts, or the actual process status
and every stdout/stderr byte when one does. The aligned baseline must retain its
original eight output words; crashes/timeouts are not rewritten as successes.

Native Windows execution at `7c8fd27` accepts all five adequate image extents,
including the four unaligned cases, and the program returns its original eight
words. The three insufficient extents fail CreateProcess with actual winerror
193/errno 8; no child executes. The complete native report is frozen at
`pe/reference/pe32-geometry-windows-v1.json`. Source/case hashes and all original
native outputs/errors are required by default. Physical M4 development execution
reproduces five successes and three preflight rejections, normally and with forced
rebase. Strict-reference revision `d08bcc4` passes all three PE and 24 conformance
CI jobs; downloaded clean Windows/hosted Mac records and fresh clean physical M4
execution at that same revision agree on exact inputs/sources, successful output
bytes and the finite acceptance/rejection pattern. See validation for exact runs.

The comparator checks identical inputs/revisions, all positive output bytes,
backend diagnostics/actual forced relocation, and finite acceptance/rejection.
Raw native CreateProcess errors remain separate from Alkyhol's status-78 preflight
errors; they are not claimed numerically equivalent. Crashes, observer failures,
unknown OS errors and timeouts cannot pass as compatible rejections. Rounded
allocation is a bounded Alkyhol policy consistent with these observations, not a
measurement of Windows page/query layout. Microsoft's format still specifies
alignment; the measured tolerance is finite native behavior rather than claimed
specification compliance. This does not prove the original game loads or executes.

## Certificate-directory loading observer

A separate owned PE32 corpus varies the non-mapped certificate directory while
leaving image/code/import data unchanged. Eight cases cover absence, an empty
certificate header, malformed bytes, out-of-file offset/length, header bytes,
unaligned range and overflowing range. Only the directory pair and two explicit
eight-byte certificate appends vary. The builder requires the unchanged frozen
owned PE32 base and rejects force-integrity inputs; no game binary is accepted.

Native Windows execution at `8a9e0fb` accepts all eight cases and returns every
original output byte. Its complete report is frozen at
`pe/reference/pe32-certificates-windows-v1.json`; the builder/source/case identities
and native outputs are required by default. Physical M4 development execution
agrees on all eight outputs in normal and forced-rebase runs. The new paired CI
comparator requires a clean identical revision, exact inputs, raw output and actual
forced relocation. Strict-reference revision `70ef3d4` passes all three PE and
24 conformance jobs. Downloaded clean native Windows/hosted Mac reports and fresh
clean physical M4 execution at that same revision agree on all eight exact inputs
and outputs, including normal/forced-rebase host execution. See validation for
exact completed runs.

Loading a PE and verifying its signature are separate operations. No signature
verification API is added or reported successful. This corpus measures ordinary
loading without an explicit code-integrity request; FORCE_INTEGRITY inputs fail
Alkyhol preflight. The retained metadata never supplies unchecked file reads or
mapped ranges. This finite loading evidence does not establish game startup.

## Executable self-export observer

The original MIT no-CRT i386 executable imports actual GetModuleHandleA/W(NULL)
and GetProcAddress to inspect/call its named/ordinal stdcall exports and read/write
exported data. Native Windows at `272fb60` returns all 26 recorded DWORDs, including
module/image-base identity, named aliases, successful stdcall calls, initialized
and BSS data access, an actual BSS write, ordinal-only visibility and last-error
behavior. Tested missing/case-mismatched names return error 127; tested ordinals
below/above the exported range return error 182. Successful lookups preserve the
probe's previous last-error values. The complete actual native report is frozen
unchanged at `pe/reference/pe32-exports-windows-v1.json` and required by default.

Physical M4 development normal/forced-rebase execution agrees on all 26 words.
Strict-reference revision `7b7dcff` passes all three PE and 24 conformance CI
jobs. Downloaded clean native Windows/hosted Mac reports and fresh clean physical
M4 execution at that same revision agree on all 26 words and frozen input/source
identities. Both host records include actual forced rebase. The paired
comparator checks exact executed bytes/source identity, all raw output and decoded
words, actual forced relocation, and separate native/host diagnostic contracts.
No game binary enters CI; the local game still stops before entry at another
unsupported startup feature.

Only validated contiguous direct self-export tables are enabled at startup.
Every consumed metadata byte must be initialized readonly non-executable section
data without HIGHLOW/IAT writes. The cached table therefore survives mapping
unchanged. Exported function/data addresses retain their original image RVAs;

existing AMD64 EXE export gate remains. These are finite API/ABI observations, not
game compatibility or a complete Windows loader.

Microsoft documents [current-process module lookup](https://learn.microsoft.com/en-us/windows/win32/api/libloaderapi/nf-libloaderapi-getmodulehandlea)

## FS/TEB observer

last-error coherence in both directions between direct FS storage and real Win32
APIs, including 10,000 import transitions. Native Windows at `d25c411` returns all
16 raw DWORDs; its complete report is frozen unchanged at
`pe/reference/pe32-teb-windows-v1.json` and required by default. These are finite
observations of self identity, stack containment and API/field coherence, not
native allocation layout or a complete TEB implementation.

Physical M4 development normal/forced-rebase runs agree on all 16 words. A separate
host-only repeat runs the same owned body twice on one loaded image, with two full
output blocks and two actual segment-restoration/descriptor-cleanup checks.
`--teb-info --repeat` is an explicit trusted-observer diagnostic, not CRT/process
restart. Strict-reference revision `2ad7650` passes all three PE and 24
conformance CI jobs. Downloaded clean native Windows/hosted Mac reports and fresh
clean physical M4 execution at that same revision agree on all 16 words and exact
frozen input/source identities. Both host reports pass normal, forced-rebase and
repeat/restoration checks. See validation for exact completed runs.
The comparator requires exact PE/source identity, raw words, actual relocation,
segment cleanup diagnostics and both repeated blocks; missing references, crashes
and joint drift fail.

This milestone supplies the FS/TEB foundation. Static TLS data is covered by the
following milestone; TLS callbacks remain unsupported. No game code has executed. All prior frozen PE32 fixtures remain unchanged.
Microsoft's [TEB description](https://learn.microsoft.com/en-us/windows/win32/api/winternl/ns-winternl-teb)
notes that internal layouts can change; the measurements above come from this
owned native observer. See validation for exact completed runs.

## Compiler static TLS data and unresolved zero fill

The `pe32-tls-data` owned PE32 executes real compiler-generated __declspec(thread)
reads/writes through FS:[0x2c], the loader-written index and SECREL offsets. Native
Windows at `8efdd37` agrees on all 24 raw DWORDs: initialized and zero-initialized
variables, a relocated pointer initializer, alignment/template containment and
mutations. The private value changes while the original image template retains
its initial bytes. The complete native record is frozen unchanged at
`pe/reference/pe32-tls-data-windows-v1.json` and required by default.

Physical M4 development normal/forced-rebase runs agree on all 24 words. Strict-
reference revision `f07f550` passes all three PE and 24 conformance CI jobs.
Downloaded clean native Windows/hosted Mac reports and fresh clean physical M4
execution at that same revision agree on all 24 words and exact frozen input/source
identities. Both strict paired comparisons pass, including actual forced relocation
and host-only second-entry rejection. See validation for exact completed runs. A host-only second
entry request emits one complete baseline body and then fails explicitly with
status 78; static TLS images are single-entry, and no CRT restart is invented.
Older non-TLS observer repeat behavior remains available.

Metadata inspection (`Image::static_tls32`) retains requested template/zero-fill
extents and checked callback RVAs without executing them. Runtime startup accepts
only empty callback arrays and SizeOfZeroFill=0. Metadata must be initialized
readonly data with exact HIGHLOW pointer fixups; the writable aligned index cannot
overlap the template or loader writes. Requested storage is bounded to one MiB.
The runtime copies the **mapped, relocated/bound template** into separate aligned
low storage, assigns opaque slot zero for this isolated EXE/main thread and installs
its TEB vector. Native slot numbers/allocation layout are not compared; the probe
checks consistent indexed lookup and real data behavior. Dynamic TLS APIs, DLL TLS,
callbacks and guest threads remain unsupported.

The separate original `pe32-tls` probe requests 16 extra zero-fill bytes. Its first
native run observed a post-template byte OR of 255; three further runs observed
255, 255 and 247. The original source/PE is unchanged, and full raw records are
retained in `pe32-tls-zerofill-observation-windows-v1.json` and
`pe32-tls-zerofill-repeats-windows-v1.json` under `pe/reference/`. Cause and allocation
extent remain unmeasured; these are diagnostic observations, never a parity
profile or semantics to reproduce by filling bytes with those values. Nonzero
SizeOfZeroFill fails Alkyhol preflight pending investigation. This limitation is
independent of compiler-zero-initialized variables **inside** the copied template.
The new data fixture has a distinct identity and checks only declared storage.
No reference or original input was weakened to make a comparison pass.

The local game clears its static TLS data preflight and now stops at unsupported
load configuration before entry. No game code executed.
See validation for exact completed runs and evidence boundaries.

## Legacy load configuration and compiler GS

Native Windows executes seven owned compiler-GS cases, preserving the tested
64-byte default cookie and custom/zero/small seeds, while changing the 72-byte
default cookie. The four-case length matrix independently confirms that this
observed action follows the **declared structure size**, even when the directory
length disagrees. Both full native records are frozen unchanged under
`pe/reference/pe32-load-config*-windows-v1.json` and required by default.

`Image::legacy_load_config32` inspects 64/72-byte records through the longer backed
span, including SafeSEH suffix data behind a short directory. It retains image RVAs,
descriptive versions/timestamp and checked handler entries. Other active fields,
mutable/fixed-up nonpointer metadata, invalid targets and cookie/TLS/IAT aliases
fail. Inspection does not register or dispatch exceptions. Startup supports empty
handler lists; nonempty SafeSEH remains an explicit unsupported gate.

For supported startup, host system entropy changes only the default cookie in a
declared 72-byte record, before executing any protected guest frame. Other tested
seeds/legacy forms are retained. This compares opaque properties and real compiler
checks, not equal RNG output or cryptographic strength. Entropy failures have no
fixed-value success fallback.

Physical M4 development normal/forced-rebase runs reproduce all eleven positive
records. The invalid-frame case deliberately executes UD2 in the owned checker;
Windows 0xc000001d and host SIGILL remain separate raw observations, with an exact
begin marker. Valid frames take the compiler's inline fast path. This is not
Windows exception-dispatch evidence or a rule accepting arbitrary crashes.
Strict same-clean-revision Windows/hosted Mac/physical M4 comparisons pass at
`1a844a6`; all three PE and 24 conformance CI jobs pass. See validation for runs.

The local game stops at SafeSEH before entry; no game code has executed. Work now
prioritizes its exception handling and bundled DLL startup. Focused checks accompany
edits, with full validation batched at larger milestones as requested by the user.
