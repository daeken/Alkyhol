# Experimental PE32 execution in a 64-bit Rosetta host

Alkyhol now executes an unchanged owned i386 Windows PE32 binary on the physical
M4 through a 64-bit Mach-O host. This is checked loading plus CPU mode gates, not
static instruction rewriting, a 32-bit Mach-O, or a general Win32/game runtime.
The user-selected next application target is their local DAOrigins executable;
it has not executed. Its current first preflight stop is the loader's unvalidated
unaligned-SizeOfImage header case. Game binaries, packaged game wrappers and all
header/import inventories remain ignored/local and are never sent to CI.

```sh
python3 tools/build_pe32_fixture.py
python3 tools/run_pe32_probe.py --fixture local/pe/pe32/pe32.exe --output local/pe/pe32/observation.json
python3 tools/translate_pe32.py /path/to/trusted.exe --output local/pe/program32-macos
local/pe/program32-macos --inspect
local/pe/program32-macos
```

## CPU and address-space contract

The host links with a 4-KiB __PAGEZERO so low guest address space is available.
MAP_32BIT allocations are checked below 4 GiB without MAP_FIXED or replacing host
mappings. Image bases are 64-KiB aligned; the stack has inaccessible guard pages.
Two unused LDT slots (512/513) supply flat 32-bit code/data descriptors and remain
reserved for this process lifetime. Occupied slots fail before being overwritten.
On this Rosetta version, automatic LDT allocation and multi-selector installation
abort the process; the implementation explicitly queries these slots and installs
one descriptor per call. Initial isolated experiments observed those limitations.

Original MIT assembly switches into 32-bit code using a far return. Low far-jump
gates switch to 64-bit code at imports, return to the saved host stack, call Rust,
then resume a per-import 32-bit RET-immediate stub with the correct stdcall cleanup.
A final gate returns the DWORD entry result to the host. Host nonvolatile registers
and DS/ES/SS selectors are saved/restored; EBX/ESI/EDI/EBP survive API calls. FS/GS
are not repurposed into Windows state. No Wine implementation code is copied.

## Loader and API subset

`Image::parse_i386` explicitly selects PE32/i386 headers, 32-bit ImageBase,
directory offsets and four-byte import slots. Existing AMD64 constructors still
reject PE32. Bitness, section bounds/W^X, initialized entry, directory backing,
names/ordinals, arithmetic/32-bit address limits and overlapping fixups are checked.
HIGHLOW relocation may adjust initialized instruction operands or section data
before RX/RO protections; header/BSS writes and unsupported kinds fail. IAT/HIGHLOW
write overlap is rejected. Current startup gates reject exports, static TLS,
load config/CFG, bound/delay imports, exception directories, CLR and other existing
unsupported features. Unaligned SizeOfImage remains unsupported pending a separate
native geometry observer; the game header is not silently rewritten or ignored.

`LoadedImage32::load(bytes, rebase, &process)` preflights every feature/import,
creates the checked image, low gates and guarded stack, and borrows ProcessContext
through cleanup. Unsafe `enter` executes trusted code; it rejects nested entry.
Only kernel32 GetLastError, SetLastError, GetStdHandle and synchronous WriteFile are
bridged. Standard handles use actual host stream handles behind explicit four-byte
proxies. Arguments are copied before host calls, allowing output pointers to
alias guest argument words without retaining a Rust reference to that storage.
WriteFile buffers/count output must lie in permitted image/stack ranges,
with DWORD-aligned stack/count pointers;
overlap must be NULL, and writes are bounded to one MiB. Unknown imports fail
before entry; unsupported runtime forms terminate with diagnostic/status 78.

There is no FS/TEB/PEB, static TLS, CRT startup, DLL execution/loading, callbacks,
SEH, guest threads, Windows syscall or binary graphics/COM support on this path.
Only integer/stdcall results are implemented; full floating-point/exception state
and additional calling conventions remain separate. Input instructions are trusted
native code, not statically validated or sandboxed. Existing PE64 runtime/source
compatibility and direct Metal APIs remain separate, preserved paths.

## Finite evidence

An original MIT no-CRT PE32 observer executes 10,000 imported last-error round trips,
checks four-byte pointer width and original relocated data-pointer identity, and
writes eight exact DWORDs using a real five-argument stdcall WriteFile. An assembly
canary checks EBX/ESI/EDI/EBP/ESP preservation and a one-byte 32-bit INC wrapping
EAX; that opcode has different semantics in 64-bit mode. Physical M4/Rosetta normal
and forced-rebase runs pass. The identical PE is transferred to native Windows
for independent execution through the existing workflow. Downloaded clean native
Windows/hosted Mac records and clean physical M4 execution at `63b6f53` agree on
all eight raw words and exact executed PE/source identities. The complete native
record at `pe/reference/pe32-windows-v1.json` is frozen and required by default.
Hashes cover exact source/executed PE bytes and clean revision.
See [validation](validation.md) for actual revisions/results.

Synthetic portable tests separately cover header formats, truncation, width/address
bounds, named/ordinal/fallback imports, malformed tables and HIGHLOW boundaries,
including real instruction-operand targets. Host units check buffer permissions,
stack edges and overflow without executing fake mappings. Compiler checks enforce
the process-guard lifetime. These finite observations do not establish CRT, game
startup or rendering compatibility.

Primary background: Wine's [macOS WineConf 2022 presentation](https://indico.freedesktop.org/event/2/contributions/92/attachments/87/140/Wine%20on%20macOS%20State%20of%20the%20Union%20-%20WineConf%202022.pdf)
documents 32-bit code segments under Rosetta. [Wine 9.0 release notes](https://list.winehq.org/hyperkitty/list/wine-announce%40list.winehq.org/message/TB7WYKWZF4DWNQLWN3XZM2NLEAF6MKST/)
describe the 32-bit PE/64-bit Unix boundary. [Pinned Wine 11.0 source](https://github.com/wine-mirror/wine/blob/wine-11.0/dlls/ntdll/unix/signal_x86_64.c)
shows macOS LDT usage; Apple's installed `i386/user_ldt.h` declares the LDT APIs.
Microsoft's [PE/COFF format](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format)
and [stdcall contract](https://learn.microsoft.com/en-us/cpp/cpp/stdcall) define the
binary layout and calling convention. External implementation descriptions are
background; the physical tests above are Alkyhol's actual execution evidence.
