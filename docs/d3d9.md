# D3D9 over wgpu

The user authorized D3D9 implementation after the original DAO executable reached
Direct3DCreate9. D3D9 now has a separate `alkyhol-d3d9` Rust GPU crate using pinned
open wgpu 27.0.1, with Metal, Vulkan and D3D12 backend features. The existing direct
Metal D3D12, Sakura and MiniEngine paths are unchanged. Backend portability is not
portability of the macOS/Rosetta PE32 loader. Physical execution below is Metal;
Vulkan and D3D12 backend execution have not yet been measured.

## Current milestone: original tutorials 01 and 02

The unchanged Microsoft Tutorial 02 InitD3D, InitVB, Render and Cleanup bodies now
also execute as PE32 through Alkyhol. Its real vertex-buffer Lock/memcpy/Unlock,
SetStreamSource, SetFVF and DrawPrimitive calls produce the original 300×300
colored triangle. The original file is pinned in the same manifest and retains
its upstream bytes and MIT license. Its interactive entry/message loop is
replaced by the owned finite witness, just as in Tutorial 01.

The initial fixed-function draw contract is XYZRHW|DIFFUSE (FVF 0x44), one
20-byte stream and triangle lists, with D3D9's integer pixel-center convention,
default clockwise front faces and back-face culling. An explicit WGSL shader
lowers that fixed-function state through open Naga/wgpu. These tutorials contain
no HLSL or legacy shader bytecode; this is not evidence of SM1–3 translation.
Hardware rasterization/interpolation generates the colors. Texture stages,
transformation/lighting, other FVF layouts, programmable shaders, index buffers,
custom viewports/render states and general primitive types remain unimplemented.

Vertex buffers have real checked low shadow storage, bounded locks, initialized
byte ranges and retained device bindings. The draw uploads those actual bytes
to a wgpu vertex buffer. Bound storage remains drawable after the caller releases
its external buffer reference, and unbinding/device teardown releases the internal
binding. The witness checks ownership, rejected out-of-range locks, retained bytes
and rendering after external Release. This does not assert native numerical
IUnknown reference-count results for internal bindings.

The triangle witness reports every one of 90,000 RGB pixels. The independent
Windows comparison requires identical coverage decisions and an RGB per-channel
difference no greater than one, declared before the native triangle observation.
The clear witness still requires exact RGB bytes. This tolerance does not cover
geometry/coverage differences. Physical M4 passes both original tutorial PEs,
all 177 PE library tests, backend/PE Clippy, three backend host units and two actual
GPU tests. The latter test triangle interior/background and reverse-winding culling.
Native triangle agreement is not yet observed.

## Initial clear/readback contract

The PE32 layer supplies actual low-memory IDirect3D9, IDirect3DDevice9 and
IDirect3DSurface9 COM identities, 32-bit stdcall gates, reference counts and parent
lifetimes. Native Rust/Objective-C pointers never become guest interface pointers.
QueryInterface supports each implemented interface and IUnknown on one identity.
Unsupported virtual slots terminate explicitly rather than returning S_OK.

The factory selects one real hardware GPU through wgpu. The adapter description
uses actual backend metadata and explicitly identifies Alkyhol as the compatibility
implementation; its synthetic compatibility GUID is not a Windows driver/WHQL
record. SDK version 32 is accepted. A full device-caps surface, mode enumeration,
monitor mapping and capability negotiation are not implemented yet and must not
advertise arbitrary capabilities.

Initial devices support windowed HAL/software-vertex-processing creation, one
BGRA8 backbuffer (A8R8G8B8 or X8R8G8B8), no multisampling or depth buffer, discard
swap effect and default presentation interval. This software-vertex-processing
creation flag does not imply a CPU rasterizer or implemented general vertex
processing. Current GPU operations are whole-target color clear and real padded
GPU readback. BeginScene/EndScene maintain validated scene state. System-memory
offscreen surfaces support GetRenderTargetData, metadata and whole-surface locks.
Surface identity and its external device reference survive repeated backbuffer
queries. Unsupported resets, resource formats, locking modes, shaders, draw calls,
textures/index buffers and general fixed-function state remain separate work; the
limited vertex-buffer extension above is now implemented.

Present currently performs a GPU readback followed by the existing real AppKit
window presentation. It is a deliberately synchronous initial path, not a zero-copy
swapchain or measured D3D9 presentation-timing equivalent. Rendering pixels are
produced by the GPU, not synthesized on the CPU. General fullscreen, present
rectangles/dirty regions, device-loss/reset recovery and frame pacing are absent.

## Unchanged Microsoft tutorial and independent witness

`samples/d3d9/create_device/CreateDevice.cpp` is copied byte-for-byte from
Microsoft's MIT-licensed DirectX-SDK-Samples repository at
`07e3eaa10e7dd026ec9d95fe326db2d5c4227e1b`, path
`C++/Direct3D/Tutorials/Tut01_CreateDevice/CreateDevice.cpp`. The adjacent provenance
manifest pins the source digest, upstream path and license; builds verify it.

The owned C++ witness includes that unchanged file and calls its actual InitD3D,
Render and Cleanup. A finite harness replaces the interactive entry/message loop,
uses a 65×3 client and observes its complete blue backbuffer via D3D9's real
GetRenderTargetData/LockRect interfaces. The sample source is not rewritten into
Rust. The finite compatibility include supplies its Windows/COM declarations;
independent Windows SDK assertions check sizes, field offsets and virtual slots.
Known source methods retain their correct stdcall signatures. Unused virtual
slots in this finite header are placeholders, not implemented interfaces.

The witness additionally checks IUnknown identity, parent identity, live device
status, begin/end rejection, cleanup and the actual guest stack. Every reported
RGB pixel is compared exactly; X8 alpha is intentionally unspecified and excluded.
It does not establish triangle rasterization, shader execution, native on-screen
presentation parity, DAO rendering or game compatibility.

    python3 tools/observe_d3d9_create_device.py

    cargo test --manifest-path d3d9/Cargo.toml --locked --offline
    cargo test --manifest-path d3d9/Cargo.toml --locked --offline -- --ignored --nocapture

Physical M4 passed the original tutorial PE and all 195 RGB pixels, 177 PE library
tests, PE/backend Clippy and the explicit native GPU test. That GPU test checks
all BGRA bytes of several clears, padded rows, target independence and rejected
uninitialized readback/invalid extents. GPU tests are marked ignored for ordinary
host-only runs and are run explicitly in the D3D9 workflow. Its producer uploads
one literal PE and source/file identities; Windows executes the exact same PE
against native D3D9. A workflow definition is not a native result.

## Prior startup evidence correction

CI 42555112613 passed hosted/native brush, cursor, DLL-worker, Winsock, registry
and directory checks; the older worker/GDI comparisons also passed. It retained
full-path, message-queue and software-context mismatches and exposed a section
lifetime error: after closing all section handles, native OpenFileMapping fails
even while views retain the backing data. The previous view-retains-name
assumption was wrong. The failed report remains evidence, not an accepted match.

The implementation now keeps namespace leases with handles, while views retain
only backing descriptors. Recreating a name creates a new backing inode, preserving
old views without aliasing or truncation. The owned PE checks absence after last
handle close, continued old-view coherence and independent zeroed recreation while
old views remain mapped. Local checks pass; a new Windows comparison is required.

The first original DAO run with this layer passes Direct3DCreate9 and executes
GetAdapterCount/GetAdapterIdentifier against the actual GPU. It next stops
explicitly at IDirect3D9::GetAdapterModeCount (slot 6). This run has dirty runtime
sources captured locally; a clean revision rerun is still needed. It does not
reach D3D9 device creation or draw any DAO frame.

The clean original DAO rerun at `71ef46e` confirms the factory/adapter path and
GetAdapterModeCount stop. CI 42559007382 passed hosted Metal and the identical-PE
producer, but its independent Windows SDK assertion rejected the adapter record
size: PE32 D3DADAPTER_IDENTIFIER9 is 1100 bytes, not the initially assumed 1104.
All checked member offsets passed. The runtime write and assertion are corrected,
and the PE witness now guards both ends of the exact 1100-byte output. The initial
failed native job remains recorded; the native pixel step did not run in it.

CI 42559416643 passes the corrected independent Windows SDK layout assertions,
including the exact 1100-byte adapter record. Its native pixel step stopped before

## Native and portable observations

CI 42560083730 (revision 5a188e2) passes the independent Windows SDK assertions
and the full native clear/COM witness: all 217 output words agree with hosted
Metal, including every one of 195 RGB pixels and the adapter output guards.
Its literal clear PE SHA-256 is
`32c20bbc52bbf4007e95c151dd3a1efd2c4d16d2250a3cb5a9621c09a8cfa538`.

That run's triangle witness fails one invalid-input assertion: the native driver
accepts Lock(offset=60,size=1) on a 60-byte vertex buffer, whereas Alkyhol rejects
it to preserve owned-storage bounds. Native acceptance does not establish legal
out-of-range access. The failed report remains a failure. Independent examination
of the exact same captured PE outputs finds all 90,000 coverage decisions equal;
89,387 RGB pixels agree exactly and the other 613 differ by at most one channel
value. No raster/pixel tolerance was changed. The literal triangle PE SHA-256 is
`af48f093407548b0a2273420340afcdef8b37f241213f148b06633eeb5a4299e`.

The next witness replaces that invalid-caller assumption with a defined GetDesc
metadata check, retaining all original rendering, binding-lifetime, pixel and
stack checks. Alkyhol's bounded invalid-lock policy has its own overflow/range
unit and remains explicitly outside native equivalence for invalid calls. All
178 PE library tests and Clippy pass physically after this correction. A complete
passing native triangle witness is still pending.

CI 42560238748's Vulkan-software job passes all five backend tests through Mesa
Lavapipe on Linux. This is genuine Vulkan execution but software rendering, not
physical Vulkan GPU evidence or a portable PE/window bridge. Its Metal/native
