# D3D9 over wgpu

The user authorized D3D9 implementation after the original DAO executable reached
Direct3DCreate9. D3D9 now has a separate `alkyhol-d3d9` Rust GPU crate using pinned
open wgpu 27.0.1, with Metal, Vulkan and D3D12 backend features. The existing direct
Metal D3D12, Sakura and MiniEngine paths are unchanged. Backend portability is not
portability of the macOS/Rosetta PE32 loader. Physical execution below is Metal;
Vulkan software execution is independently validated on Linux. Physical Vulkan
GPU and wgpu D3D12 backend execution have not yet been measured.

## Current milestone: original tutorials 01 and 02

The unchanged Microsoft Tutorial 02 InitD3D, InitVB, Render and Cleanup bodies now
also execute as PE32 through Alkyhol. Its real vertex-buffer Lock/memcpy/Unlock,
SetStreamSource, SetFVF and DrawPrimitive calls produce the original 300×300
colored triangle. The original file is pinned in the same manifest and retains
its upstream bytes and MIT license. Its interactive entry/message loop is
replaced by the owned finite witness, just as in Tutorial 01.

The initial fixed-function draw contract is XYZRHW|DIFFUSE (FVF 0x44), one
20-byte stream and triangle lists, with D3D9's integer pixel-center convention,
default clockwise front faces and back-face culling. An explicit WGSL shader
lowers that fixed-function state through open Naga/wgpu. These tutorials contain
no HLSL or legacy shader bytecode; this is not evidence of SM1–3 translation.
Hardware rasterization/interpolation generates the colors. Texture stages,
transformation/lighting, other FVF layouts, programmable shaders, index buffers,
custom viewports/render states and general primitive types remain unimplemented.

Vertex buffers have real checked low shadow storage, bounded locks, initialized
byte ranges and retained device bindings. The draw uploads those actual bytes
to a wgpu vertex buffer. Bound storage remains drawable after the caller releases
its external buffer reference, and unbinding/device teardown releases the internal
binding. The witness checks ownership, descriptor metadata, retained bytes
and rendering after external Release. This does not assert native numerical
IUnknown reference-count results for internal bindings.

The triangle witness reports every one of 90,000 RGB pixels. The independent
Windows comparison requires identical coverage decisions and an RGB per-channel
difference no greater than one, declared before the native triangle observation.
The clear witness still requires exact RGB bytes. This tolerance does not cover
geometry/coverage differences. Physical M4 passes both original tutorial PEs,
all 178 PE library tests, backend/PE Clippy, three backend host units and two actual
GPU tests. The latter test triangle interior/background and reverse-winding culling.
Native Windows agrees on identical-PE triangle coverage and RGB within one;
CI 42561453681 passes all three D3D9 jobs. Details and hashes are recorded below.

## Initial clear/readback contract

The PE32 layer supplies actual low-memory IDirect3D9, IDirect3DDevice9 and
IDirect3DSurface9 COM identities, 32-bit stdcall gates, reference counts and parent
lifetimes. Native Rust/Objective-C pointers never become guest interface pointers.
QueryInterface supports each implemented interface and IUnknown on one identity.
Unsupported virtual slots terminate explicitly rather than returning S_OK.

The factory selects one real hardware GPU through wgpu. The adapter description
uses actual backend metadata and explicitly identifies Alkyhol as the compatibility
implementation; its synthetic compatibility GUID is not a Windows driver/WHQL
record. SDK version 32 is accepted. A full device-caps surface, mode enumeration,
monitor mapping and capability negotiation are not implemented yet and must not
advertise arbitrary capabilities.

Initial devices support windowed HAL/software-vertex-processing creation, one
BGRA8 backbuffer (A8R8G8B8 or X8R8G8B8), no multisampling or depth buffer, discard
swap effect and default presentation interval. This software-vertex-processing
creation flag does not imply a CPU rasterizer or implemented general vertex
processing. Current GPU operations are whole-target color clear and real padded
GPU readback. BeginScene/EndScene maintain validated scene state. System-memory
offscreen surfaces support GetRenderTargetData, metadata and whole-surface locks.
Surface identity and its external device reference survive repeated backbuffer
queries. Unsupported resets, resource formats, locking modes, shaders, draw calls,
textures/index buffers and general fixed-function state remain separate work; the
limited vertex-buffer extension above is now implemented.

Present currently performs a GPU readback followed by the existing real AppKit
window presentation. It is a deliberately synchronous initial path, not a zero-copy
swapchain or measured D3D9 presentation-timing equivalent. Rendering pixels are
produced by the GPU, not synthesized on the CPU. General fullscreen, present
rectangles/dirty regions, device-loss/reset recovery and frame pacing are absent.

## Legacy programmable shader milestone (bounded, open compiler)

The PE32 COM path now executes owned literal SM3 vertex/pixel bytecode through
separately built **vkd3d-shader 2.1 → SPIR-V → Naga 27.0.3 → WGSL → wgpu**.
The Rust runtime uses the real compiler output and reflection. It does not replace
shader math with a fixed shader. The compiler is LGPL-2.1-or-later, pinned to
upstream `fb7f9ff3c1f8d972ee6f1b8c6a92caf6c8ba1e10`; the release archive is pinned
by SHA-256 in the bootstrap/provenance manifest. Its license is retained under
`d3d9/licenses/`. Only the shader compiler target is built: no Wine runtime or
gated Apple converter is required. The Vulkan SONAME configure input is unused
metadata for the unbuilt runtime, not a claimed Vulkan installation.

The helper reflects actual signatures/resources, maps VS/PS resource sets, and
links VS output semantics against the actual following PS signature with upstream
`vkd3d_shader_build_varying_map`. Naga's automatic Y inversion is disabled because
this compiler output preserves D3D clip space. An explicit triangle-only adapter
keeps Vulkan PointSize computations in private storage; point draws remain
unsupported. A Naga wrapper applies D3D9's half-pixel vertex-position convention
without changing the original vertex math or varyings.

New low stdcall COM objects implement vertex/pixel shader creation, exact original
bytecode GetFunction, device ownership, binding/getters, external/bound lifetimes,
float constants, and bounded float vertex declarations. The guest bytecode reader
walks SM2.0/3.0 token lengths and comments to END rather than searching payloads.
SM1's implicit operand encoding remains unsupported by this reader. Initial GPU
resources are stage float constants and viewport, one float stream, triangle lists
and the existing BGRA8 target. Integer/bool buffers, texture/sampler resources,
other primitive types and general shader-model coverage are not implemented.
Caps still report zero shader versions; this finite shader witness is not a
promise to implement the entire shader model or DAO's effects.

The backend now offers actual single-sample, non-lockable D16_UNORM storage,
implicit device depth creation and explicit Create/Set/GetDepthStencilSurface.
Metadata reports format 80, usage DEPTHSTENCIL and default pool; bound and implicit
surface identities use the same checked, acyclic ownership rules. Only D16 is
advertised. Other requested depth formats and all enabled stencil operations
remain unsupported; they are not silently mapped to lower/different precision.
Z enable, writes and the eight comparison functions affect real GPU pipelines.
Depth clears affect only requested depth contents; unsupported rectangular clears,
larger-depth subregions, depth locks, stencil and nonzero bias still fail.

Physical M4 passes seven GPU tests, including actual nearer/farther occlusion,
write suppression, reversed/never/always tests, depth-only clear preservation,
attachment lifetime and explicit invalid/uninitialized operations. The owned
--depth PE passes all 2,100 words: implicit and explicit surface metadata,
bindings after external release, null attachment failure and two full-frame
zero/one depth-clear comparisons through original legacy bytecode. New native
Windows and software Vulkan comparisons are pending. Original DAO now negotiates
and creates D16 instead of getting a fabricated attachment on query; it reaches
dynamic vertex/index buffer allocation. The bounded object limit was increased
to 4,096 after its actual shader batch exhausted 128; no shaders were dropped.

## Dynamic/indexed buffer milestone

Default-pool vertex and 16/32-bit index buffers now have actual checked low
storage, accurate usage/descriptors, DISCARD/NOOVERWRITE and validated locks.
The buffer bound is 64 MiB after DAO's real roughly 2 MiB request exceeded the
prototype 1 MiB limit. Discard clears initialized-range tracking; read-only and
write-only contracts are distinguished. Index bindings retain storage without
retaining the device in a cycle, and getters restore external references.

Programmable triangle-list DrawIndexedPrimitive normalizes the original index
values against MinVertexIndex, combines the signed base with the stream offset
using checked arithmetic, then uploads real GPU vertex/index buffers and uses
wgpu draw_indexed. No vertices/triangles are discarded or expanded into a canned
image. Other primitive types and indexed fixed-function FVF draws fail explicitly.
Shader feedback checks now apply only to sampled slots actually used by the shader.
HRESULT failures are logged even if the original caller elects to ignore them.

Physical M4 passes an indexed quad GPU test with four shared vertices, invalid
index ranges, and the 2,100-word --indexed PE: 16-bit and dynamic 32-bit indices,
DISCARD/NOOVERWRITE, retained bindings, descriptor/parent queries, negative base,
nonzero minimum/start index and nonzero stream offset. Both complete output frames
remain unchanged. PE (183 library plus integration/doctests) and Clippy pass.
New native indexed comparison is pending. Original DAO now passes dynamic vertex
and index buffer creation/upload and reaches GetSwapChain; no game draw exists.
